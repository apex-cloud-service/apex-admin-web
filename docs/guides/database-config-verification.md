# 数据库配置功能验证清单

> 适用版本：1.2.0 ｜ 页面路径：`/system/database` ｜ 更新日期：2026-09-27

## 1. 功能定位

数据库配置页面（[src/views/system/database/index.vue](../../src/views/system/database/index.vue)）用于**部署配置采集与导出**：
管理员填写目标数据库连接参数后，可测试连接并一键生成 YAML / env / docker-compose 三种格式的部署配置。

> **注意**：该页面**不是**运行时数据库管理控制台，不提供库表浏览、SQL 执行等能力。

## 2. 前置条件

| 项目 | 要求 |
|------|------|
| 后端服务 | `apex-scaffold` 已启动（接口模块 8080），且已实现 `/admin-api/v1/database/**` 三个接口 |
| 登录态 | 管理员账号已登录，且角色拥有 `system:database:view` 权限 |
| 菜单注册 | 已执行菜单 SQL（`scripts/database/menu-init.sql`），`sys_menu` 中存在数据库配置菜单 |
| 前端构建 | `npm run dev`（开发）或构建产物已部署（生产） |

## 3. 接口清单

接口封装见 [src/api/database.ts](../../src/api/database.ts)，类型定义见 [src/types/index.ts](../../src/types/index.ts)（`DatabaseConfig` / `DatabaseTestResult` / `DeploymentConfigResult` / `CurrentDatabaseInfo`）。

| 接口 | 方法 | 路径 | 功能 |
|------|------|------|------|
| 连接测试 | POST | `/admin-api/v1/database/test` | 验证数据库连接参数，成功时返回数据库版本 |
| 生成部署配置 | POST | `/admin-api/v1/database/generate-config` | 生成 YAML / env / docker-compose 配置 |
| 当前库信息 | GET | `/admin-api/v1/database/current` | 只读查询当前运行数据库的类型与版本 |

## 4. 验证步骤

### 4.1 菜单与路由可达

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 登录后查看侧边栏「系统管理」 | 出现「数据库配置」菜单项 |
| 2 | 点击菜单 | 进入 `/system/database` 页面，无 404、无空白 |
| 3 | 刷新页面（history 模式直接刷新） | 页面正常回显，不 404 |
| 4 | 使用无 `system:database:view` 权限的账号 | 菜单不可见或后端返回 403 |

### 4.2 当前库信息（GET /admin-api/v1/database/current）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开页面（或点击「刷新信息」类入口） | 页面展示当前数据库类型与版本 |
| 2 | 浏览器 Network 面板检查请求 | `GET /admin-api/v1/database/current` 返回 `Result{code:0}`，`data` 含 `type` / `version` |

### 4.3 连接测试（POST /admin-api/v1/database/test）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 选择数据库类型 | MySQL 自动填充端口 3306；PostgreSQL 自动填充端口 5432 |
| 2 | 填写主机 / 端口 / 数据库名 / 用户名 / 密码，选择部署环境 | 表单校验通过（必填项、端口范围） |
| 3 | 点击「测试连接」（目标库真实可达） | 返回成功提示，展示数据库版本 |
| 4 | 故意填错密码或主机后点击「测试连接」 | 返回失败原因提示，页面不崩溃 |
| 5 | 必填项留空提交 | 表单校验拦截，不发请求 |

### 4.4 生成部署配置（POST /admin-api/v1/database/generate-config）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 连接测试通过后点击「生成配置」 | 弹出配置导出对话框 |
| 2 | 切换查看 YAML / env / docker-compose 三种格式 | 各格式内容完整，连接参数正确回显 |
| 3 | 点击「一键复制」 | 剪贴板内容与展示一致 |
| 4 | 检查生成内容 | 密码以占位符/环境变量形式出现，**不以明文回显到配置正文**（以后端实际实现为准） |

## 5. 安全验证要点

- [ ] **密码不落库、不持久化**：填写密码后刷新页面，表单不残留密码；localStorage / sessionStorage 中无密码明文
- [ ] **密码仅一次性使用**：密码仅随单次「测试连接 / 生成配置」请求提交，前端状态在操作后不保留
- [ ] **传输安全**：生产环境通过 HTTPS 传输（请求体含密码）
- [ ] **权限控制**：后端对三个接口校验 `system:database:*` 权限，无权限账号调用返回 403
- [ ] **生成配置的安全建议**：页面安全提示明确说明密码应通过环境变量或密钥系统注入，而非硬编码

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 菜单不显示 | 菜单 SQL 未执行，或账号无 `system:database:view` 权限 | 执行 `scripts/database/menu-init.sql` 并核对角色权限，重新登录 |
| 页面 404 | 菜单 `component` 与 `VIEW_REGISTRY` 键名不一致 | 确认为 `system/database/index`（已注册于 `src/router/dynamic.ts`） |
| 测试连接一直失败 | 后端不可达、目标库网络隔离或账号密码错误 | 确认后端 8080 可达、目标库防火墙放行；失败提示会带 `traceId`，可与后端日志联动排查 |
| 生成配置按钮不可用 | 未先通过连接测试 | 先完成连接测试再生成配置 |
| 接口 401 | 登录态失效 | 重新登录（前端会自动处理 Token 刷新，刷新失败才跳登录页） |
