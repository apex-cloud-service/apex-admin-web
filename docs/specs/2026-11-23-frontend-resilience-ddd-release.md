# 前端韧性、领域边界与发布能力优化规格

## 背景

`apex-admin-web` 是 Vue 3 + TypeScript 管理端，当前 FE-029 仍承担全量 API 核对、Podman 真实链路和遗留 R5 问题。新前端优化需独立管理，不能把旧任务未完成的接口验收转为“优化完成”。

## 目标

1. 建立页面、API、状态管理、共享组件和权限边界的现状及依赖基线。
2. 评估首屏/路由 chunk、重复依赖、长列表和高频交互的性能，并先采集可重复指标。
3. 评估 API 超时、取消、错误映射、并发请求、缓存失效及安全重试边界；非幂等操作不自动重试。
4. 核查日志/trace 上下文、前端错误观测、静态资源版本和部署切换/回滚能力。
5. 分波次实施有证据、可回滚且与后端契约兼容的改进，更新测试、脚本、配置、文档和报告。

## 影响面

- 代码范围按基线盘点后由 FE-030 租约逐批明确；任务全域审查不代表全域修改。
- 默认不改 API URL、请求/响应字段、认证刷新、租户头、权限判断和后端接口契约。
- 网关/Ingress/静态托管的灰度与蓝绿由部署层负责；前端仓只核实资源版本兼容和客户端缓存策略，不声称可独自完成流量切换。
- 配置、流水线和静态资源缓存策略若影响部署，由 R0 串行协调并补相应规格和回滚方案。

## 兼容性

- 遵守前端 `AGENTS.md`、TypeScript/Vue 既有约定及权限/租户隔离语义。
- 不对 POST/PATCH 等非幂等写入加入自动重试；缓存必须定义用户、租户和权限维度的隔离键与失效条件。
- 分包/懒加载须保持路由守卫、动态菜单和权限路由行为；发布资源须支持旧页面与新资源短期共存或明确刷新策略。
- 性能目标在建立基线后确认，不预设无证据的 bundle、LCP 或并发阈值。

## 回滚方案

- 每波独立、最小化代码和配置改动，记录基线 SHA 与反向操作。
- 前端代码按波次 revert；静态资源发布恢复前一版本并清理/调整 CDN 缓存时限。
- 若出现权限、租户、认证或 API 契约变化，停止该波并回退，不以 UI 兼容层掩盖后端问题。

## 验收标准

- 现状矩阵覆盖全部主要页面域、API 导出、状态/组件边界、路由和发布配置，并区分静态发现与动态验收。
- 每项改动有对应单测或 E2E；`vue-tsc --noEmit`、`vitest run`、生产构建、E2E 与前端红线扫描通过。
- 新报告来自本次实际执行，区分成功、失败、跳过与环境未验证；不继承旧报告冒充新结果。
- 独立 R5 复核最终 diff，必改项清零；FE-029/BE-043 遗留仍按原任务验收。
