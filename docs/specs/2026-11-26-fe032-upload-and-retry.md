# FE-032 上传与请求重试修复契约

> 2026-11-26 补充执行契约。关联用户已批准的 FE-032 修复计划与任务卡；不修改后端端点、DTO、租户/认证/权限链路。最终以独立复核及本轮测试证据验收。

## 上传

- 普通上传复用当前 multipart 端点；sex 映射和 fileName→objectName 不变。
- beforeUpload 顺序为 MIME 校验、可选图片压缩、按处理后大小选择普通或分片上传；超限且合法的分片文件不进入裁剪，普通图片可进入裁剪。
- 压缩失败应拒绝本次上传并提示，不静默绕过已启用的处理；压缩后的文件重新做大小边界判断。
- 分片仍复用现有 init/upload/merge；数据参数、5MB 分片大小及 FileUploadResult 结构不变。
- 裁剪/粘贴的 XHR Promise 需等待真实 load/error/timeout/abort 结果；成功须为 HTTP 2xx 且业务 code=0。
- 无效 JSON、业务失败、HTTP 错误、启动错误及网络错误均结束 loading；失败只提示一次，不向后台自动重试非幂等上传。
- 无论如何必须先校验 MIME；大小判定使用实际上传文件，不能以原文件大小掩盖处理后的超限结果。

## 读取重试

- retryRequest 不接入 Axios 自动刷新链路，不改变 request.ts 的 401 单飞机制。
- 默认只重试识别到的网络/超时错误和 HTTP 5xx；4xx、未知错误和业务验证错误不重试。
- shouldRetry 只能收窄该集合，不能放行 4xx 或未知业务错误。
- 仍只允许幂等读取使用；不得把本工具自动附加到创建/修改/删除、上传或其他非幂等接口。

## 验收

1. 非法 MIME 超限文件不会调用分片 init。
2. 压缩后小于/大于单发上限分别走普通/分片，分片使用处理后的数据。
3. 裁剪与分片互斥；裁剪确认 loading 持续至 XHR 终结，错误不会悬挂 Promise。
4. 针对伪造 Canvas/XHR 的单测明确只验证编排，不冒充真实 Canvas/网络验证。
5. 4xx、未知错误不重试，5xx/网络允许有限次数重试，原错误保留。
6. 类型、单元、生产构建及 mock Chromium E2E 通过；真实后端验证与独立复核按实际结果记录。
